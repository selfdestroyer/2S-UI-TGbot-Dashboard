## 1. Архитектура

```text
                         [ Покупатель ]                    [ Администратор ]
                          │          │                            │
             браузер,     │          │ Telegram                   │ Telegram
             VPN-клиент   ▼          ▼                            ▼
              ┌────────────────┐   ┌──────────────────────────────────────┐
              │ Nginx :443     │   │ vpn-bot (bot.py + panel_api.py)      │
              │ SUB_DOMAIN     │   │  • заявки → bot_data.db (orders)     │
              └──┬──────────┬──┘   │  • выдача/продление → REST API ──────┼──┐
        /        │          │ /sub/│  • чтение клиентов ↓ (только чтение) │  │
                 ▼          ▼      └──────────────────┬───────────────────┘  │
     ┌──────────────────┐ ┌─────────────────────┐     │                      │
     │ vpn-dashboard    │ │ 2S-UI: подписки     │     │      2S-UI: apiv2    │
     │ app.py :8000     │ │ :2096 /sub/<имя>    │     │      :2095 /app/apiv2│◄─┘
     └────────┬─────────┘ └──────────┬──────────┘     │      (Token)
              │ только чтение        │                │
              ▼                      ▼                ▼
        ┌──────────────────────────────────────────────────────┐
        │  База панели /usr/local/s-ui/db/s-ui.db  (пишет только панель) │
        └──────────────────────────────────────────────────────┘
```

* **Чтение** клиентов (поиск подписок пользователя, напоминания, статистика, дашборд) — напрямую из `s-ui.db` в режиме `mode=ro`.
* **Запись** (создание, продление клиента) — только через REST API панели. Прямая запись в базу не обновила бы пользователей в sing-box и на узлах кластера.
* Свои данные (заявки, история напоминаний, очередь удаления сообщений) бот хранит в `bot_data.db`.

## 3. Настройки (.env)

Файл `/var/www/2S-UI-TGbot-Dashboard/.env`, права `600`. Ключи из таблицы ведёт `install.sh` (мастер и `reconfigure`), свои ключи и комментарии он не трогает. После ручной правки — `systemctl restart vpn-bot vpn-dashboard`.

### Основные

| Ключ | Пример | Описание |
| :--- | :--- | :--- |
| `BOT_TOKEN` | `1234567890:ABC…` | Токен бота от @BotFather |
| `ADMIN_TG_ID` | `123456789` | Telegram ID администратора: ему приходят чеки, ему доступно `/admin` |
| `BOT_USERNAME` | `my_vpn_bot` | Юзернейм бота без `@` (ссылки на дашборде и странице 404) |
| `PROJECT_NAME` | `My VPN Service` | Название сервиса в боте и на дашборде |
| `SUPPORT_BOT_USERNAME` | `my_support` | Юзернейм поддержки без `@` |
| `SERVICE_GROUP_NAME`, `SERVICE_GROUP_URL` | | Название и ссылка инфо-канала |
| `TIMEZONE` | `Europe/Helsinki` | Часовой пояс дат в сообщениях бота (install.sh прописывает его в юнит systemd) |

### Оплата и тарифы

| Ключ | Пример | Описание |
| :--- | :--- | :--- |
| `CARD_NUMBER` | `2202 0000 0000 0000` | Номер карты; из него строится текст реквизитов |
| `PAYMENT_REQUISITES` | `Карта: <code>…</code>` | Свой текст реквизитов (HTML, `\n` — перевод строки); если задан, заменяет `CARD_NUMBER` |
| `TARIFFS` | `30:200,90:570:5,180:1080:10,365:2000:15` | `дни:цена[:скидка%]` через запятую. Если все сроки ≤ 24, запись считается старой, в месяцах: 1→30, 3→90, 6→180, 12→365 дней, остальные ×30 |

### Автовыдача подписок

| Ключ | Пример | Описание |
| :--- | :--- | :--- |
| `PANEL_API_URL` | `https://panel.example.com:2095/app/apiv2/` | Адрес apiv2. Домен должен совпадать с `webDomain` панели, иначе панель отвечает 403 |
| `PANEL_API_TOKEN` | | API-токен панели (заголовок `Token`). Даёт полный доступ к панели |
| `PANEL_INBOUND_IDS` | `1,3,9` | ID входящих, к которым подключаются новые клиенты |
| `SUB_TRAFFIC_GB` | `250` | Лимит трафика в месяц, ГБ; `0` — без лимита и без сброса |
| `SUB_DEVICE_LIMIT` | `2` | Лимит одновременных IP (`limitIp`); `0` — без лимита |
| `SUB_RESET_DAY_OF_MONTH` | `1` | Число месяца для сброса трафика (1–31); `0` — каждые 30 дней от покупки |
| `SUB_GROUP` | `buyer` | Группа в панели для купленных подписок; пусто — не задавать |

**Версия панели.** Автовыдача работает только на 2S-UI 1.8.3 и новее (`MIN_PANEL_VERSION` в `panel_api.py`): до неё `edit` заменял строку клиента целиком, а не накладывал поля, и продление стёрло бы ключи и входящие. Версию бот берёт из `apiv2/status?r=sys` (`appVersion`): при старте (`check_panel_version`) — на старой панели переключается в ручной режим и пишет администратору; если панель недоступна — проверяет ещё раз перед первой выдачей (`PanelAPI.ensure_supported`), и до записи в панель дело не доходит.

Если пуст любой из `PANEL_API_URL`, `PANEL_API_TOKEN`, `PANEL_INBOUND_IDS`, бот при старте пишет в лог «подписки выдаются вручную» и работает в ручном режиме (см. [§6](#ручной-режим)).

### Панель и дашборд

| Ключ | Пример | Описание |
| :--- | :--- | :--- |
| `DB_PATH` | `/usr/local/s-ui/db/s-ui.db` | База панели (только чтение) |
| `BOT_DATA_DB` | `/var/www/…/bot_data.db` | Служебная база бота |
| `MAIN_DOMAIN` | `example.com` | Домен панели для ссылок на подписку |
| `PANEL_PORT` | `2096` | Порт подписок панели |
| `PANEL_SUB_URL` | `https://example.com:2096/sub` | Полный адрес подписок без имени (install.sh собирает из `subDomain`, `subPort`, `subPath` панели) |
| `SUB_DOMAIN` | `sub.example.com` | Поддомен дашборда; с нестандартным портом — `sub.example.com:8443` |

## 4. Работа с панелью 2S-UI

### Таблица `clients` (то, что использует бот)

| Колонка | Смысл |
| :--- | :--- |
| `id` | ID клиента; бот хранит его в заявке на продление |
| `name` | Уникальное имя, часть всех ссылок (`/sub/<name>`, `SUB_DOMAIN/<name>`) |
| `enable` | Включён ли клиент. Панель сама выключает истёкших и исчерпавших трафик |
| `expiry` | Окончание, unix-секунды; `0` — бессрочно |
| `volume`, `up`, `down` | Лимит и расход трафика, байты |
| `limit_ip` | Лимит одновременных IP |
| `auto_reset`, `reset_days`, `reset_day_of_month`, `next_reset` | Периодический сброс трафика |
| `tg_id` | Telegram ID владельца — основной признак привязки |
| `desc`, `remark` | Описание; бот пишет туда `tg://user?id=ID \| ID`, а для старых клиентов ищет в них Telegram ID |
| `group` | Группа клиента в панели |
| `inbounds`, `config`, `links` | Входящие, учётные данные по протоколам, сгенерированные ссылки |

### Как бот находит подписки пользователя

`find_subscriptions_by_tg_id()` отбирает клиентов с `tg_id = ID` или с ID внутри `desc`/`remark`, затем `extract_tg_id()` проверяет точное совпадение: сначала `tg_id`, затем `desc`/`remark` как число из 5+ цифр или первое число из 6–15 цифр в тексте. Поэтому клиенты, созданные до автовыдачи, с ID в Description, тоже находятся.

### Что делает `PanelAPI`

Все запросы — к `PANEL_API_URL` с заголовком `Token`, ответ панели `{success, msg, obj}`; при `success: false` бросается `PanelAPIError` с текстом панели.

* **`create(tg_id, days)`** — `POST save`, `object=clients`, `action=new`:
  * `name` — 8 случайных символов `[0-9a-zA-Z]`; при «already exists» до трёх попыток;
  * `config` — `random_configs(name)`: ключи для 15 протоколов, как их генерирует интерфейс панели (сама панель ключи не создаёт: без `config` клиент не сможет подключиться);
  * `inbounds = PANEL_INBOUND_IDS`, `expiry = сейчас + days`, `volume`, `limitIp`, расписание сброса, `desc = tg://user?id=ID | ID`, `tgId`, `group = SUB_GROUP`.
* **`extend(client_id, days, tg_id)`** — читает клиента, затем `action=edit` только с изменяемыми полями (панель накладывает их на сохранённую строку):
  * `expiry = max(текущий срок, сейчас) + days`; бессрочную подписку (`expiry = 0`) не трогает;
  * `enable = true` — панель выключает истёкших и сама обратно не включает;
  * `tgId`; `desc` — только если оно пустое, равно ID или было сгенерировано ботом (в том числе старый формат `https://t.me/… | ID`); `group` — только если у клиента нет группы.

После записи панель сама обновляет пользователей во входящих sing-box. Побочный эффект любого `edit`: панель пересобирает поле `links` (тот же набор ссылок, порядок может измениться).

### Часовой пояс сброса трафика

Дату следующего сброса (`next_reset`) панель считает по своему часовому поясу (`timeLocation` в настройках панели), а не по `TIMEZONE` бота. Пояса должны совпадать — иначе сброс «1-го числа» придётся, например, на 23:00 последнего дня месяца по местному времени. При смене пояса в настройках панель пересчитывает `next_reset` у всех клиентов с месячным сбросом.

## 5. Данные

### База панели `s-ui.db`

Только чтение (см. выше). Бот и дашборд открывают её как `file:…?mode=ro`, а systemd монтирует её папку только для чтения.

### Служебная база бота `bot_data.db`

| Таблица | Назначение |
| :--- | :--- |
| `orders` | Заявки на оплату (см. ниже) |
| `sub_labels` | Свои названия подписок: `client_id` (ключ), `tg_id` владельца, `label`, `updated_at` |
| `notification_history` | Отправленные напоминания: `client_name`, `telegram_id`, `notification_type` (`7d`, `3d`, `12h`, `expired`, `traffic90`, `traffic100`), `expiry_ts` — период: срок подписки или, для трафика, дата следующего сброса. Уникальность по `(client_name, notification_type, expiry_ts)` — после продления или сброса напоминания приходят заново |
| `scheduled_deletions` | Очередь удаления сообщений рассылки: `chat_id`, `message_id`, `delete_at` |

**`orders`**

| Колонка | Смысл |
| :--- | :--- |
| `id` | Номер заявки («Заявка №…»), он же в кнопках `approve:<id>`, `reject:<id>`, `retry:<id>` |
| `tg_id`, `username`, `full_name` | Покупатель |
| `tariff_code`, `days`, `price` | Тариф на момент покупки (смена `TARIFFS` старые заявки не меняет) |
| `kind`, `target_client_id`, `target_client_name` | `new` или `extend` и какую подписку продлеваем |
| `status` | `pending` → `processing` → `approved` / `failed`; или `rejected` |
| `client_id`, `client_name`, `expiry` | Что выдано |
| `error` | Текст последней ошибки выдачи |
| `user_msg_id` | Сообщение покупателю «Заявка №… на проверке», которое бот обновляет после решения |
| `created_at`, `decided_at` | Время создания и решения |

Ежедневный бэкап `bot_data.db` — в `/root/2s-ui-tgbot-backups` (7 дней).

## 6. Покупка, подтверждение и выдача подписки

### Покупатель

1. «💳 Купить подписку» (`buy_subscription`) — витрина `tariffs_screen()`: у сроков длиннее месяца цена за месяц (месяцев — округлённо: 90 дней = 3, 365 = 12), самый выгодный по цене за день отмечен 🔥 «выгоднее всего» (если это не самый короткий срок).
2. Выбор тарифа (`buy_tariff:<код>`, код вида `30d`). Если автовыдача включена и у пользователя есть подписки, состояние `choosing_target`: кнопки «Продлить «название» (23 дн.)» (`buy_target:<id>`) и «Новая подписка» (`buy_target:new`). ID подписки проверяется по списку, сохранённому в состоянии, — чужую продлить нельзя.
   **Продление конкретной подписки** (`renew:<id>` — из карточки и напоминаний): владение проверяется по Telegram ID, затем та же витрина, и после выбора срока — сразу оплата, без вопроса «продлить или новую».
3. Реквизиты, состояние `waiting_for_receipt`: что оплачивается и три шага (перевести, прислать чек, дождаться проверки). Реквизиты в старом формате install.sh («ПЕРЕВОД ПО НОМЕРУ КАРТЫ» капсом) бот показывает в новом виде.
4. Фото или файл → создаётся заявка в `orders`, чек уходит администратору, покупатель получает «⏳ Заявка №… на проверке» (его id сохраняется в `user_msg_id`). Любой другой ответ — просьба прислать чек.

Если заявку не удалось сохранить, чек всё равно уходит администратору — без кнопок и с пометкой «выдайте вручную».

### Администратор

Под чеком — карточка заявки и кнопки «✅ Подтвердить» / «❌ Отклонить». Подпись всегда собирается заново из заявки (`order_caption`), статусы не накапливаются.

**Подтверждение** (`approve:<id>`, `retry:<id>`):
1. Кнопку может нажать только `ADMIN_TG_ID`.
2. Заявка атомарно переводится из `pending`/`failed` в `processing` (`claim_order`). Если она уже в другом статусе — алерт «Заявка уже обработана». Так двойное нажатие или нажатие с двух устройств не выдаёт подписку дважды.
3. Подпись: «⏳ выдаю подписку…», вызов `PanelAPI.create` или `PanelAPI.extend`.
4. Успех → `approved`, подпись «✅ ВЫДАНО: <имя> до <дата>». Сообщение о заявке у покупателя меняется на «✅ выполнена», и приходит новое — с кнопкой «🚀 Подключиться» (Mini App `https://SUB_DOMAIN/<имя>`), «Дать название» (для новой подписки) и «Мои подписки».
5. Ошибка → `failed` с текстом ошибки, подпись «⚠️ Ошибка выдачи: …», кнопки «🔁 Повторить» и «❌ Отклонить».

**Отклонение** (`reject:<id>`) — из `pending` или `failed` в `rejected`; сообщение о заявке меняется на «❌ отклонена», и приходит сообщение с кнопкой поддержки.

**Перезапуск во время выдачи.** При старте бот переводит зависшие `processing` в `failed` с пометкой «проверьте панель перед повтором»: запрос к панели мог успеть выполниться.

**Старые кнопки** `approve_sub:` / `reject_sub:` — у чеков, пришедших до появления заявок, — только уведомляют покупателя, как раньше.

### Ручной режим

Без `PANEL_API_URL`/`PANEL_API_TOKEN`/`PANEL_INBOUND_IDS`: выбора «продлить или новая» нет, «✅ Подтвердить» переводит заявку в `approved` и отправляет покупателю «оплата подтверждена», а под чеком появляется напоминание создать подписку в панели вручную. Администратор создаёт клиента и вписывает Telegram ID в Description (или `tgId`).

## 7. Остальные функции бота

* **`/start` и «← Главное меню»** — приветствие с лимитами из `SUB_DEVICE_LIMIT` и `SUB_TRAFFIC_GB`, кнопки «💳 Купить подписку», «📦 Ваша подписка», «Поддержка» и «⚙️ Сервисное меню (Админ)» для администратора. Эмодзи у покупателя — точечно: один в заголовке сообщения и на главных кнопках; статусы и строки с данными — словами, кнопки возврата — «← …». Подписи с размерами — через `cap()`, а не `str.capitalize()`, который превратил бы «ГБ» в «гб».
* **«📦 Ваша подписка»** (`my_subscription`) — одна подписка: сразу карточка; несколько: список «название · 23 дн.» (`sub:<id>`); нет подписки: предложение купить или статус заявки на проверке. После показа экрана `notify_admin_subscription_view()` шлёт `ADMIN_TG_ID` уведомление: «✅ Запрос подписки» (имя, @юзернейм, Telegram ID, подписки с названием, статусом, сроком и ссылкой на дашборд) или «⚠️ Попытка доступа без подписки» (с номером заявки на проверке, если есть). Нажатия самого админа не уведомляются. Срабатывает на `my_subscription`, то есть и на кнопку «← Все подписки» из карточки. Под одиночной карточкой и списком — `GROUP_NOTE` (новости в группе), ссылка на группу только в кнопке.
  * Карточка (`sub_card`): статус словом, срок и остаток дней, полоса трафика, дата обновления трафика, лимит устройств. Кнопки: «🚀 Подключиться» (`web_app` — дашборд как Mini App), «💳 Продлить» (`renew:<id>`), «Переименовать» (`rename:<id>`), «Открыть в браузере» (обычная ссылка, запасной вариант).
  * Статус (`sub_state`) по тем же правилам, что цвет на дашборде: «истекла», «трафик закончился», «отключена»; «скоро закончится» (≤ 5 дней), «трафик на исходе» (≥ 90%); иначе «активна».
  * Переименование: шесть готовых названий (`label:<id>:<n>`) или своё сообщением (состояние `RenameState.waiting_for_label`, до 24 символов, пробелы схлопываются), «Убрать название» (`label:<id>:clear`). Все действия проверяют, что подписка принадлежит нажавшему.
* **`/admin`** — статистика (всего профилей, активных, срочных и бессрочных, уникальных Telegram ID активных клиентов) и рассылка.
* **Рассылка** — текст или фото с подписью, рассылается всем уникальным Telegram ID активных клиентов. Время жизни: 1, 3, 6, 12, 24 часа, 3 или 7 дней, своё значение или без удаления; по истечении сообщения удаляются из чатов.

## 9. Веб-дашборд

`app.py` (служба `vpn-dashboard`, Uvicorn на `127.0.0.1:8000` за nginx):

**Mini App.** Бот открывает дашборд кнопкой `web_app` — страница та же. Telegram передаёт в адресе `tgWebAppData`; только тогда `index.html` подгружает `telegram-web-app.js`, вызывает `ready()` и `expand()` и открывает внешние ссылки через `openLink` / `openTelegramLink`. Ссылки импорта (`hiddify://`, `incy://`, `throne://`) мини-приложение открыть не может: Telegram пропускает из него только `http(s)` (на Android — `ERR_UNKNOWN_URL_SCHEME`). Поэтому в мини-приложении кнопка «Открыть в …» вызывает `openLink("/open/<приложение>/<имя>")`. Это служебная страница `app.py` (`open_in_app`): для известного приложения и существующей подписки она строит ту же ссылку импорта, что и `index.html`, и первой строкой `<head>` переходит по ней. Встроенный браузер Telegram на Android передаёт такую ссылку приложению и, раз страница ещё не загрузилась, сразу закрывается (`Browser.openInExternalApp` → `onInstantClose()`), так что пользователь видит только запуск приложения. Если приложение не установлено, на странице остаются кнопка импорта, ссылки на установку и «← Вернуться к подписке». Неизвестное приложение или имя — 404.
Для обычного браузера страница подписки понимает и `?open=<приложение>`: выбирает приложение, убирает параметр из адреса и запускает импорт. Ссылка импорта в обоих случаях строится из самой подписки — из адреса берётся только выбор приложения из известного списка. В карточке бота есть ещё запасная кнопка «Открыть в браузере». Настройка в @BotFather для этого не нужна.


* `GET /api/subscription/{имя}` — JSON: активность, срок, дни до окончания, трафик, дата сброса. `Cache-Control: private, max-age=300`. Даты панели в секундах и миллисекундах обрабатываются одинаково.
* `GET /open/{приложение}/{имя}` — служебная страница импорта для Mini App (см. выше), `Cache-Control: no-store`.
* `GET /{имя}` — если клиент существует, отдаёт `index.html` с подставленными `PROJECT_NAME`, `MAIN_DOMAIN`, `PANEL_PORT`, `PANEL_SUB_URL`, юзернеймами ботов (с экранированием); иначе страница 404 со ссылкой на бота. `index.html` читается на каждый запрос.

Nginx (`vpn-sub.conf`, генерирует `install.sh`): HTTPS с Let's Encrypt, `/` → дашборд, `/sub/` → порт подписок панели с её доменом в SNI и `Host`, лимит 30 запросов в минуту с IP.

## 10. Установка и обновление

Шаги мастера и режимы `install.sh` описаны в [README](../README.md#-установка-на-сервер). Технические детали:

* **Колонки базы:** мастер проверяет, что в `clients` есть всё, что читают бот и дашборд (`REQUIRED_COLUMNS`: в том числе `limit_ip` — 2S-UI 1.7.0+, `tg_id` — 1.8.0+, `total_up`/`total_down`).
* **Проверка работы** (после установки и в `status`) при заданном токене включает «API панели принимает токен» и «версия панели подходит для автовыдачи»; итоговая сводка пишет режим (автовыдача или вручную) и предупреждает, если без HTTPS не откроется мини-приложение.
* **Версия панели** (`panel_app_version`): из `apiv2/status`, без токена — из `sui -v`. Ниже 1.8.3 мастер предупреждает, что автовыдача не заработает; версия видна в сводке и в `status`.
* **Сертификат панели** (`fix_panel_cert_renewal`, при установке, `reconfigure` и `update`): для сертификатов certbot из `webCertFile`/`subCertFile` с `authenticator = standalone` проверяет, отдаёт ли nginx `/.well-known/acme-challenge/` для их доменов; если нет и у домена нет своего сайта nginx — создаёт `vpn-panel-acme.conf` (только этот путь и переадресация на HTTPS), затем переводит продление на `webroot` (`certbot reconfigure`, а на certbot < 2.3 — правкой файла продления с проверкой `--dry-run` и откатом) и продлевает, если осталось меньше 30 дней. Панель 2S-UI 1.5.4+ перечитывает сертификат сама. `status` показывает срок и способ продления; `uninstall` этот сайт не удаляет.
* Шаг «Автовыдача» собирает `PANEL_API_URL` из `settings` панели: `webDomain` (иначе `MAIN_DOMAIN`), `webPort` (2095), `webPath` (`/app/`), схема `https`, если задан `webCertFile` или `webAcme`. Токен проверяется запросом `GET <PANEL_API_URL>inbounds`; ошибка — предупреждение, а не остановка установки. Список входящих выводится из таблицы `inbounds`.
* `.env` обновляется по списку `ENV_KEYS`, прежняя версия копируется в `/root/2s-ui-tgbot-backups`.
* `update`: `git pull` в `/root/2S-UI-TGbot-Dashboard`, снимок текущей версии, `rsync --delete` в `/var/www/…` (файлы, удалённые из репозитория, убираются; `venv`, `.env`, `*.db` и их служебные файлы, `index.html.original_backup*` не трогаются), обновление зависимостей и юнитов, проверка служб, при сбое — откат к снимку.

## 11. Безопасность

* Службы работают от пользователя `vpnbot` в песочнице systemd (`NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`). Писать можно только в папку проекта.
* Файлы базы панели принадлежат root с правами `600`, поэтому службам дана единственная привилегия `CAP_DAC_OVERRIDE` — для чтения. Папка базы панели в песочнице только для чтения, сами службы открывают базу в `mode=ro`.
* Подписки меняются только через API панели. API-токен даёт полный доступ к панели (в том числе выгрузку базы), поэтому хранится только в `.env` с правами `600` и не выводится ни в логи, ни в сообщения.
* Кнопки подтверждения и отклонения проверяют `ADMIN_TG_ID`; тариф и цена берутся из сохранённой заявки, а не из данных кнопки.
* Ссылки и имена в сообщениях экранируются; nginx ограничивает частоту запросов к дашборду.
* `.env`, базы и `venv` исключены из Git (`.gitignore`).

## 12. Диагностика

```bash
journalctl -u vpn-bot -n 100 --no-pager      # последние сообщения бота
sudo bash /var/www/2S-UI-TGbot-Dashboard/install.sh status
sqlite3 /var/www/2S-UI-TGbot-Dashboard/bot_data.db \
  "select id, tg_id, kind, days, status, client_name, error from orders order by id desc limit 10"
```

| Симптом | Причина и решение |
| :--- | :--- |
| В логе при старте «подписки выдаются вручную» | Пуст `PANEL_API_URL`, `PANEL_API_TOKEN` или `PANEL_INBOUND_IDS`; заполните и перезапустите бота |
| Админу пришло «Автовыдача подписок отключена» | Панель 2S-UI старше 1.8.3 — обновите её и перезапустите бота |
| `status`: ❌ «сертификат панели продлевается…» | Меньше 14 дней или продление `standalone` при занятом 80-м порту — `install.sh update` переведёт его на `webroot` |
| `invalid token` | Токен удалён или истёк — создайте новый в панели |
| `403: адрес PANEL_API_URL не совпадает…` | В адресе IP или другой домен; нужен `webDomain` панели |
| `панель недоступна` / `не ответила за 20 секунд` | Панель остановлена или неверный порт: `systemctl status s-ui` |
| `client name … already exists` три раза подряд | Практически невозможно при случайных именах; проверьте, не создаёт ли клиентов что-то ещё |
| Покупатель не видит подписку в «📦 Ваша подписка» | У клиента нет `tgId` и Telegram ID в Description; впишите ID в панели |
| Сброс трафика показан на последний день месяца | Часовой пояс панели отличается от вашего — смените его в настройках панели ([§4](#часовой-пояс-сброса-трафика)) |
| «Заявка уже обработана» при первом нажатии | Заявку уже подтвердили или отклонили с другого устройства — смотрите статус в `orders` |
