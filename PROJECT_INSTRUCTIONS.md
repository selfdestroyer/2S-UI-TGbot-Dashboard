## 1. Общее описание и архитектура

**VPN-Bot** — это асинхронный Telegram-бот на базе фреймворка `aiogram 3`, созданный для автоматизации работы коммерческих и приватных VPN-сервисов, использующих панель управления **2S-UI** (или аналогичные форки X-UI с базой SQLite).

### Ключевые возможности:
* **Авторизация по Telegram ID:** бот проверяет привязку аккаунта Telegram в описании клиента в БД панели (`desc` или `remark`).
* **Выдача ссылок подписки:** генерация прямых персональных ссылок для импорта в приложения Happ, Streisand, v2rayN, Nekobox, Shadowrocket, Sing-box, Clash и др.
* **Тарифы и ручная модерация оплат:** выбор тарифных планов, генерация реквизитов (с копированием в один клик), приём фото чеков и интерактивные кнопки одобрения/отклонения для администратора.
* **Фоновые напоминания:** автоматический асинхронный воркер проверяет даты окончания подписок и отправляет уведомления за 7 дней, 3 дня, 12 часов и в момент истечения подписки с защитой от дубликатов.
* **Сервисное меню администратора (`/admin`):** детальная статистика сервиса, количество активных и истекших клиентов.
* **Умная рассылка с автоудалением (TTL):** мастер создания рассылки с поддержкой форматированного текста, фото и инлайн-ссылок. Сообщения рассылки автоматически удаляются из чатов всех пользователей через заданное время (15 минут, 1 час, 12 часов, 24 часа или произвольный интервал), не засоряя историю переписки.

## 3. Конфигурация и переменные окружения (.env)

Настройки считываются из файла `.env` в корне проекта.

| Переменная | Пример значения | Описание |
| :--- | :--- | :--- |
| `BOT_TOKEN` | `1234567890:ABCdefGHIjklMNOpqrsTUVwxyz` | Токен Telegram-бота от `@BotFather` |
| `ADMIN_TG_ID` | `123456789` | Цифровой Telegram ID администратора |
| `DB_PATH` | `/usr/local/s-ui/db/s-ui.db` | Путь к файлу базы данных SQLite панели 2S-UI |
| `BOT_DATA_DB` | `bot_data.db` | База данных для служебных таблиц бота |
| `PROJECT_NAME` | `My VPN Service` | Название сервиса в шапках сообщений |
| `SUB_DOMAIN` | `sub.yourdomain.com` | Домен для ссылок подписок `https://{SUB_DOMAIN}/{client_name}` |
| `SUPPORT_BOT_USERNAME` | `your_vpn_support_bot` | Юзернейм контакта техподдержки (без `@`) |
| `SERVICE_GROUP_NAME` | `Официальный канал` | Название кнопки информационного канала |
| `SERVICE_GROUP_URL` | `https://t.me/your_channel` | Ссылка на новостной канал или чат сервиса |
| `PAYMENT_REQUISITES` | `💳 <b>ПЕРЕВОД...</b>` | HTML-текст реквизитов для оплаты (номер карты, СБП и т.д.) |

### Пример файла `.env`:
```env
BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz
ADMIN_TG_ID=123456789
DB_PATH=/usr/local/s-ui/db/s-ui.db
BOT_DATA_DB=bot_data.db
PROJECT_NAME="My VPN"
SUB_DOMAIN=sub.example.com
SUPPORT_BOT_USERNAME=my_vpn_support_bot
SERVICE_GROUP_NAME="Официальный канал сервиса"
SERVICE_GROUP_URL=https://t.me/my_vpn_channel
PAYMENT_REQUISITES="💳 <b>ПЕРЕВОД ПО НОМЕРУ КАРТЫ:</b>\n<code>0000 0000 0000 0000</code>\n<i>(нажмите на номер, чтобы скопировать)</i>"
```

## 4. Интеграция с базой данных 2S-UI (SQLite)

Бот подключается к файлу SQLite панели 2S-UI в режиме чтения и обращается к таблице `clients`:

* `id` (`INTEGER`) — идентификатор клиента в панели.
* `name` (`TEXT`) — системное имя клиента (используется как slug в URL подписки: `https://sub.domain/{name}`).
* `desc` (`TEXT`) / `remark` (`TEXT`) — поля описания, в одно из которых вносится Telegram ID пользователя (например: `123456789`).
* `expiry` (`INTEGER`) — время окончания подписки в миллисекундах или секундах Unix-time (0 — бессрочно).
* `enable` (`INTEGER`) — признак активности клиента (1 — активен, 0 — отключен).

## 5. Служебная база данных бота (bot_data.db)

Для внутренних нужд бот инициализирует отдельный файл SQLite (`bot_data.db`), не влияя на целостность данных панели 2S-UI:

1. **`notification_history`**:
   * Хранит записи об отправленных пользователям напоминаниях (`client_name`, `threshold_type`, `expiry_timestamp`, `sent_at`).
   * Предотвращает повторную отправку одного и того же уведомления при перезапусках бота.
2. **`scheduled_deletions`**:
   * Очередь сообщений рассылки с таймером самоуничтожения (`chat_id`, `message_id`, `delete_at`).
   * Воркер проверяет таблицу каждые 30 секунд и удаляет сообщения через Telegram Bot API, после чего очищает запись.

## 6. Пользовательский функционал (Client UX)

### Главное меню
* Доступно по `/start` или кнопке «◀️ Главное меню».
* Отображает информацию о доступных протоколах, ограничениях по устройствам и трафику.
* Кнопки: «💳 Купить подписку», «📦 Ваша подписка», «💬 Поддержка», а также «⚙️ Сервисное меню» (только для администратора).

### Личный кабинет «Ваша подписка»
* При нажатии бот ищет записи в таблице `clients`, где `desc` или `remark` содержат `message.from_user.id`.
* Если найдено: выводятся инлайн-кнопки со списком подписок в формате `{Имя} | {Дата окончания}` со ссылками на конфигурацию.
* Если не найдено: выводятся понятные инструкции и контакт поддержки.

### Оформление покупки и модерация чеков
1. Клиент выбирает срок подписки (1, 3, 6 или 12 месяцев).
2. Бот переводит пользователя в состояние ожидания чека (`BuySubscriptionState.waiting_for_receipt`), выводит реквизиты и инструкции.
3. Пользователь отправляет фото квитанции или документ.
4. Заявка с фото чека мгновенно поступает в личный чат администратора с кнопками `[ ✅ Одобрить ]` и `[ ❌ Отклонить ]`.
5. При нажатии администратором бот обновляет статус заявки у администратора и автоматически отправляет результат клиенту.

## 7. Автоматические напоминания об окончании подписки

В фоне работает корутина `notification_worker`, которая раз в час сканирует базу клиентов:

* **За 7 дней:** мягкое напоминание о скором завершении срока.
* **За 3 дня:** предупреждение о необходимости продления.
* **За 12 часов:** срочное уведомление.
* **В момент окончания:** уведомление об истечении доступа с предложением продлить тариф.

Каждое уведомление сопровождается прямой кнопкой на быструю оплату и контактом поддержки.

## 8. Сервисное меню администратора и рассылки

Администратор может вызвать сервисную панель командой `/admin` или нажатием инлайн-кнопки в главном меню.

### Метрики и статистика
* Всего клиентов в панели
* Активных подписок
* Истекших подписок
* Бессрочных клиентов
* Количество отправленных напоминаний
* Сообщений в очереди на автоудаление

### Рассылка сообщений с автоудалением по таймеру (TTL)
1. Выбор типа рассылки: **Текст** или **Фото с текстом**.
2. Ввод текста и прикрепление медиа (поддерживается HTML-разметка).
3. Возможность добавить интерактивную кнопку-ссылку.
4. Выбор времени жизни сообщения (TTL):
   * 15 минут
   * 1 час
   * 12 часов
   * 24 часа
   * Произвольное количество минут/часов
   * Без автоудаления (бессрочно)
5. Предпросмотр сообщения перед отправкой.
6. Пакетная отправка всем зарегистрированным клиентам с защитой от лимитов Telegram.
7. Фоновый демон удаляет сообщения из каждого клиентского чата ровно в назначенное время.

## 9. Инструкция администратора: привязка клиентов

Для привязки клиента в панели 2S-UI:
1. Откройте панель в браузере.
2. В настройках клиента (Inbound -> Client):
   * **Remark / Name:** желаемый логин клиента (латиницей).
   * **Desc (Description):** вставьте цифровой **Telegram ID** клиента (узнать ID можно из заявки на оплату или через `@userinfobot`).
   * **Expiry Date:** укажите дату окончания подписки.
3. Нажмите кнопку **Save / Сохранить**.
4. Теперь при нажатии «📦 Ваша подписка» клиент сразу увидит свой профиль.

## 10. Развертывание и обслуживание на сервере (Systemd)

### 1. Установка системных пакетов
```bash
apt update && apt install -y python3 python3-venv python3-pip git
```

### 2. Клонирование и настройка окружения
```bash
cd /var/www/
git clone https://github.com/your-username/vpn-bot.git
cd vpn-bot

python3 -m venv venv
./venv/bin/pip install --upgrade pip
./venv/bin/pip install -r requirements.txt
cp .env.example .env
nano .env
```

### 3. Создание Systemd-юнита
Создайте файл `/etc/systemd/system/vpn-bot.service`:
```ini
[Unit]
Description=Telegram VPN Bot Daemon
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/var/www/vpn-bot
ExecStart=/var/www/vpn-bot/venv/bin/python3 /var/www/vpn-bot/bot.py
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

### 4. Запуск и управление
```bash
systemctl daemon-reload
systemctl enable vpn-bot
systemctl start vpn-bot

# Проверка статуса
systemctl status vpn-bot

# Мониторинг логов
journalctl -u vpn-bot -f
```

## 11. Безопасность

* Никогда не коммитьте файл `.env` в публичные репозитории.
* База данных `bot_data.db` и файл `.env` добавлены в `.gitignore`.
* На сервере рекомендуется выставить строгие права на файл окружения:
  ```bash
  chmod 600 /var/www/vpn-bot/.env
  ```
